# Запуск на виртуалке

Приложение работает в одном Docker-контейнере: раздаёт сайт, принимает нажатия и сохраняет комнаты. Отдельный хостинг фронтенда не нужен.

Скрипт использует Docker без Compose, как в `ai-sdlc-game`. По умолчанию он оставляет порты `80` и `443` твоему существующему reverse proxy. Приложение доступно самой виртуалке на `127.0.0.1:8788` и контейнерам в сети `rover-rally` на `rover-rally-app:8787`.

## Если на виртуалке уже есть сайт

Установи Docker и `curl`, направь A-запись нового домена на виртуалку. Клонируй репозиторий или скопируй проект на сервер. Из корня проекта выполни от `root`:

```bash
DOMAIN='rover.example.com'
./scripts/update-vm.sh "$DOMAIN"
```

Скрипт собирает образ, сохраняет копию существующей базы, заменяет контейнер и проверяет `/health`. При первом запуске базы ещё нет, поэтому копировать нечего. Скрипт сам не обновляет исходники и не вызывает `sudo`.

Затем добавь домен в действующий reverse proxy. Для Caddy, установленного прямо на виртуалке, добавь в существующий Caddyfile:

```caddyfile
rover.example.com {
    reverse_proxy 127.0.0.1:8788
}
```

Если Caddy работает в Docker, подключи его к сети игры один раз. Например, если это прокси из `ai-sdlc-game` и контейнер по-прежнему называется `ai-sdlc-proxy`:

```bash
docker network connect rover-rally ai-sdlc-proxy
```

В его существующий Caddyfile добавь отдельный блок. Сохрани блоки других сайтов:

```caddyfile
rover.example.com {
    reverse_proxy rover-rally-app:8787
}
```

Подставь свой домен. Проверь конфигурацию и перезагрузи её обычным способом. Для контейнера `ai-sdlc-proxy`:

```bash
docker exec ai-sdlc-proxy caddy validate --config /etc/caddy/Caddyfile
docker exec ai-sdlc-proxy caddy reload --config /etc/caddy/Caddyfile
curl -fsS "https://${DOMAIN}/health"
```

У старого `ai-sdlc-game` скрипт обновления пересоздаёт Caddy и записывает конфигурацию заново. Если используешь его как общий прокси, сохрани оба сайта в его постоянной конфигурации и добавь подключение сети `rover-rally` в свой процесс запуска. После пересоздания контейнера подключи сеть снова. Скрипт этой игры существующий прокси не меняет.

## Если виртуалка свободна

Открой TCP-порты `80` и `443` в firewall виртуалки и облака. Для домена направь A-запись на сервер. Запусти:

```bash
DOMAIN='rover.example.com'
./scripts/update-vm.sh "$DOMAIN" --standalone
```

Этот режим запускает отдельный Caddy и занимает порты `80` и `443`. Caddy получает и обновляет HTTPS-сертификат. Не используй `--standalone`, если эти порты уже заняты другим сайтом.

Проверить внешний адрес и получение сертификата:

```bash
docker logs --tail 100 rover-rally-proxy
curl -fsS "https://${DOMAIN}/health"
```

Для временного запуска по IPv4 можно передать адрес вместо домена:

```bash
./scripts/update-vm.sh 203.0.113.10 --standalone
curl -fsS http://203.0.113.10/health
```

Такой адрес работает по HTTP. Для обычной игры через интернет используй домен с HTTPS.

## Обновление и данные

Обнови исходники, затем снова вызови скрипт с тем же доменом и режимом. Например, если репозиторий уже настроен на нужную ветку:

```bash
git pull --ff-only
./scripts/update-vm.sh "$DOMAIN"
```

Для отдельного Caddy добавь `--standalone`. Обновление ненадолго прерывает соединения; проводи его между гонками.

Контейнеры запускаются с `--init` и `--restart unless-stopped`. База лежит в постоянном Docker-томе `rover-rally-data`. Скрипт не удаляет этот том. Резервные копии перед обновлением хранятся на виртуалке в `/var/backups/rover-rally` с доступом только для `root`. Копия создаётся средствами SQLite, в том числе когда приложение работает. Если копирование завершится ошибкой, текущий контейнер останется запущен.

В режиме `--standalone` сертификаты сохраняются в `rover-rally-caddy-data`, конфигурация Caddy — в `/etc/rover-rally/Caddyfile`. Не удаляй том с базой и не запускай несколько экземпляров приложения с одной базой.

Для диагностики:

```bash
docker logs --tail 100 rover-rally-app
curl -fsS http://127.0.0.1:8788/health
docker ps --filter name=rover-rally
```

Локальная проверка скрипта подтверждает запуск приложения. Доступность с телефонов проверяй через внешний адрес после настройки DNS и прокси.
